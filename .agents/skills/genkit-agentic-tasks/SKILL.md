# Genkit Agentic Tasks & Orchestrator Skill

Данный скил аккумулирует архитектурные практики, паттерны проектирования и практический опыт, полученный при разработке автономного AI-оркестратора регламентных расчетных процессов (`ai_task`) в системе `buh70`.

---

## 1. Архитектурный манифест

При создании AI-оркестраторов фоновых задач придерживайтесь следующих принципов:

1. **Zero Direct DB Access (Только через REST API):**
   - AI-оркестратор и субагенты изолированы от прямого подключения к PostgreSQL/БД.
   - Любое действие выполняется исключительно через неблокирующие вызовы API бэкенда (`POST /task/<endpoint>/`).
   - Вся специфика транзакций, блокировок и хранимых процедур остается внутри бэкенда монолита.

2. **Stateless FSM Tick-Based Execution (Тиковая архитектура):**
   - Оркестратор **не должен висеть в памяти** в виде долгоживущего демона (`daemon`) в ожидании многочасовых расчетов.
   - Служба запускается планировщиком (Cron / Cloud Scheduler / Windows Task Scheduler) на короткий «тик» (1-5 секунд):
     - Считывает дамп состояния (`state/orchestrator_state.json`).
     - Опрашивает прогресс активных задач через лог-эндпоинт (`POST /task/read_log/...`).
     - Запускает следующие готовые по графу DAG задачи.
     - Сохраняет обновленное состояние и немедленно завершает процесс (`exit 0`).

3. **Hybrid AI + Deterministic FSM Decision Making (Приоритет промпта с Fallback):**
   - Если у задачи или цикла задан `prompt`, решение делегируется LLM (Google Gemini через Genkit) с получением **Structured Output (Zod)**.
   - Если `prompt` не задан (`null`) или вызов LLM упал по таймауту/ошибке сети, оркестратор **автоматически делает fallback** на детерминированные правила FSM (проверка расписания по часам, статусы предшественников).

4. **Parent Context Forwarding (Передача контекста родительской задачи):**
   - Зависимые задачи в графе (DAG) могут требовать контекст завершившихся предшественников (например, `log_id` родителя для рассылки отчетов). Оркестратор инжектирует эти параметры автоматически при диспетчеризации.

5. **Штатная обработка пустых выборок (0 записей / No-op):**
   - Отсутствие данных для обработки (например, 0 счетов в выходной день) должно фиксироваться как штатный `SUCCESS` (`count: 0`), а не `HTTP 500`. Лог в БД должен закрываться со статусом `success`, позволяя последующим шагам графа выполниться.

## 2. Структура проекта субагента

Каждый регламентный процесс организуется в виде изолированного модуля:

```text
ai_task/
├── <task_name>/
│   ├── config.json         # Декларативная конфигурация (flow, schedule, prompt, params)
│   ├── schemas.ts          # Zod-схемы входных/выходных параметров и контракты
│   ├── tools.ts            # Клиентские HTTP-инструменты обращения к API
│   ├── agent.ts            # Логика субагента (запуск + ожидание через watcher)
│   └── <task_name>.test.ts # Модульные тесты с моками
├── orchestrator/
│   ├── config.json         # Общие настройки (daily_start_time, timezone, retry)
│   ├── orchestrator.schemas.ts # FSM-схемы, контракты решений LLM
│   ├── orchestrator.agent.ts   # Ядро FSM: проверка DAG, запуск, мониторинг
│   ├── state.manager.ts        # Загрузка/сохранение orchestrator_state.json
│   └── orchestrator.test.ts    # Тесты оркестратора
├── shared/
│   ├── types.ts            # Общие типы (AsyncTaskStartResponseSchema и др.)
│   └── api_client.ts       # HTTP клиент с конфигурацией и Bearer auth
└── index.ts                # Точка входа Genkit (Flows + CLI)
```

## 4. Чек-лист при создании нового субагента

- [ ] Создан подкаталог `<agent_name>/`.
- [ ] Описан `config.json` с валидным JSON (без висячих запятых и дубликатов ключей!).
- [ ] В `schemas.ts` переиспользуется общая схема ответа старта `AsyncTaskStartResponseSchema` из `shared/types.ts`.
- [ ] В `tools.ts` функция запуска принимает `ApiClient` и валидирует ответ через Zod.
- [ ] В `agent.ts` реализован запуск и неблокирующее ожидание через `watchTaskUntilDone` из `logs_watcher`.
- [ ] Добавлен модульный тест `*.test.ts` с моками `fetch` (успешный запуск, ошибки, таймаут).
- [ ] В `orchestrator/state.manager.ts` агент добавлен в список известных директорий `KNOWN_AGENT_DIRS` и граф по умолчанию.
- [ ] Выполнены `npm run build` (`tsc`) и `npm test`.
