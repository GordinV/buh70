# Сервис генерации и поиска Viitenumber (`get_viitenumber`)

## 1. Назначение и контекст
Сервис предоставляет веб-интерфейс, работающий в двух взаимоисключающих режимах:
1. **Обратный поиск данных по viitenumber:** пользователь вводит только ссылочный номер (`viitenumber`), сервис выполняет расшифровку и возвращает учреждение (`asutus`), пояснение к счету/ребенку/контрагенту (`selgitus`).
2. **Прямой расчет viitenumber по реквизитам:** пользователь выбирает учреждение (`rekv_id`), тип (`tyyp`) и указывает номер документа / регистрационный код / личный код (`objekt_number`), сервис генерирует и возвращает `viitenumber` и сопутствующие данные.

---

## 2. Спецификация маршрутизации и безопасности
- **Маршруты Express:**
  - `GET /:hash/viitenumber` — отображение формы поиска/расчета.
  - `POST /:hash/viitenumber` — обработка отправленной формы и рендер страницы с результатами.
- **Валидация пользователя / хеша:**
  - Заглушка валидации проверяет фиксированный токен:
    `hash === '2f2b7890e7951a55d589c2bb5df2d0f59cd10877'`.
  - При несовпадении хеша возвращается HTTP `403 Forbidden` (`Juurdepääs keelatud: vigane turvakood`).
- **Авторизация сессии:**
  - Стандартная сессионная авторизация (`checkAuth`) отключена (публичный доступ по хешу).

---

## 3. Входные параметры и взаимоисключающий ввод (Mutual Exclusion)
Форма поддерживает два взаимоисключающих блока ввода:

### Блок А: Обратный поиск (Viitenumber)
- **`viitenumber`** (TEXT): ссылочный номер для обратной расшифровки.

### Блок Б: Прямой расчет (Реквизиты)
1. **Asutus `rekv_id`** (INTEGER):
   - Выпадающий список, наполняемый из базы данных PostgreSQL:
     ```sql
     SELECT id, nimetus 
     FROM ou.rekv 
     WHERE status <> 3 AND (parentid = 0 OR parentid < 999) 
     ORDER BY nimetus;
     ```
2. **Tüüp `tyyp`** (TEXT):
   - Список типов:
     - `1`: "Vanemate tasu"
     - `2`: "Kontraagent"
     - `3`: "Arve number"
3. **Dokumendi number / Reg. kood `objekt_number`** (TEXT):
   - Текстовое поле ввода.

### Поведение UI и валидация:
- На стороне клиента (JS): при вводе в поле `viitenumber` поля блока Б блокируются (`disabled`) и затеняются. При заполнении полей блока Б поле `viitenumber` блокируется.
- На стороне сервера: одновременное заполнение обоих блоков или отправка полностью пустой формы запрещены и возвращают ошибку валидации.

## 4. Обработка запросов (СУБД PostgreSQL)

### 4.1. Обратный поиск (по `viitenumber`):
```sql
SELECT libs.get_data_from_viitenumber($1::TEXT) AS data;
```
Параметр: `$1` — `viitenumber` (TEXT).
Возвращаемый JSON `data`:
```json
{
  "error": false,
  "error_description": null,
  "asutus": "Narva Linnavalitsus",
  "selgitus": "Arve number: 101, arve kpv: 01.02.2026..."
}
```

### 4.2. Прямой расчет (по реквизитам):
```sql
SELECT libs.get_viitenumber_from_regkood($1::INTEGER, $2::TEXT, $3::TEXT) AS data;
```
Параметры:
- `$1`: `rekv_id` (INTEGER)
- `$2`: `objekt_number` (TEXT)
- `$3`: `tyyp` (TEXT: `'1'`, `'2'`, `'3'`)

---

## 5. Выходные данные и пользовательский интерфейс
- **Рендеринг:** Классический SSR на Jade (`jade ~1.11.0`).
- Страница сохраняет все ранее введенные пользователем значения полей при перезагрузке.
- **Отображение результата:**
  - При успехе: карточка результата с найденным/рассчитанным `Viitenumber`, наименованием учреждения `Asutus` и детализацией `Selgitus`.
  - При отсутствии данных или ошибке: блок сообщения `error_description`.
