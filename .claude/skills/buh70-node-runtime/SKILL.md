# buh70: Node.js < 14

Бэкенд buh70 (всё, кроме `routes/ai/ai_task`) работает на **Node.js < 14**.

## Синтаксис

Код бэкенда должен работать на Node 12, поэтому нельзя использовать:
- `?.` (optional chaining) и `??` (nullish coalescing);
- `??=`, `||=`, `&&=`;
- `String.prototype.replaceAll`, `Array.prototype.at`, `Object.hasOwn`;
- top-level `await`, приватные поля классов `#x`.

После правок проверять: `grep -nE '\?\.|\?\?' <файл>` — совпадений быть не должно.

`routes/ai/ai_task` — отдельная среда (genkit, TypeScript, свой Docker), на неё это ограничение не распространяется.

## Запуск скриптов и запросов к БД

Библиотека `pg` проекта — версии 7.18. На Node >= 14 `client.connect()` молча зависает: скрипт завершается без вывода и без ошибки. Поэтому скрипты, которые подключаются к БД через `pg` проекта, запускать только под Node < 14.

Локально (Windows, nvm-windows) установлены только Node 24 и 23 — `node` в PATH не подходит для таких скриптов. Варианты:
- поставить Node 12 через nvm: `nvm install 12.22.12` и запускать его напрямую по полному пути `C:\Users\Laptop\AppData\Local\nvm\v12.22.12\node.exe script.js`, не переключая глобальную версию (`nvm use` меняет её для всей системы); установку согласовать с пользователем;
- либо попросить пользователя выполнить SQL самому и прислать результат.

Строку подключения брать из `config/default.json` (`pg.connection`) и никогда не выводить её в консоль и ответы — в ней пароль.

## Тесты

В корне проекта jest 20, он не запускает современные тесты. Тесты бэкенда гонять jest 29 из `routes/ai/ai_task`:

```
cd routes/ai/ai_task
npx jest --config '{"testEnvironment":"node"}' --rootDir . --roots ../../../test --testMatch "**/<имя>.test.js"
```

Тесты идут под локальным Node 24 — синтаксис Node 14+ они не поймают, поэтому grep-проверка выше обязательна.
